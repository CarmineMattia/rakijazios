# M2 plan — Share your local AI: pairing, devices, bot models, group grants

Status: **approved 2026-10-08** with the four recommended decisions (§11) and one change:
pairing is **OS-aware and as automatic as possible** (§1.1). **M2a is implemented** on
`feat/share-local-ai-m2a` (see §12); M2b and M2c are still plan.
Base: `main` @ `7637aad` (PR #6, M1). Design: [`share-local-ai.md`](share-local-ai.md) §5–§10.
Scope: M2 only. Usage limits and accounting stay in M3; the marketplace is M4.

Product rules that still apply: runner offline ⇒ friendly notice and **no fallback** (D1); bots
run as their owner; outbound-only runner, loopback-only model dial, hashed tokens, no open
ports; no operator/OpenRouter key as a default (D2).

## 1. What changes for the user (step by step)

### 1.1 Connect my computer (owner) — OS-aware, one action

1. **Settings → My hardware** (new tab). Empty state: *"Use a model running on your own computer
   for your bots. Nothing is opened on your computer: a small runner connects out to Rakijazios."*
2. **Add a computer** creates a one-time **pairing code** (8 characters, valid 10 minutes, single
   use) and **detects the OS** (`navigator.userAgentData.platform`, falling back to the user agent),
   with a **System** dropdown to override it and a **Start automatically when I log in** checkbox
   (on by default). The dialog then shows **one primary action with the code already in it**:
   - **Linux / macOS**: one command to paste into a terminal:
     ```bash
     curl -fsSL '<origin>/api/local-runners/install.sh' | sh -s -- --code K7QF-3MZD
     ```
     The code is passed as an **argument**, not in the URL, so it never reaches access logs.
     `install.sh` is static and generated by the server with the pinned runner version and
     every file's SHA-256. It:
     - uses Node ≥ 22.18 if installed, or downloads a **portable pinned Node.js** from nodejs.org
       and checks it against a pinned SHA-256;
     - downloads the runner files and checks each one;
     - installs to `~/.local/share/rakijazios-runner` with a `~/.local/bin/rakazo-runner` shim
       (no sudo);
     - pairs, then starts the runner. With autostart it sets up a **systemd --user** unit on Linux
       or a **launchd** agent on macOS; without it, a background process.
   - **Windows**: **Download the installer** gives `Rakijazios-connect.cmd` with the code baked in.
     The browser builds it from the pairing response, so the code is not in any URL.
     Double-clicking it runs `install.ps1` through PowerShell 5.1+ (no admin):
     - portable pinned Node.js (zip, SHA-256 checked) when needed;
     - checked runner files under `%LOCALAPPDATA%\Rakijazios\runner`;
     - pair, start hidden, and a Startup-folder entry for autostart.
     SmartScreen may warn ("More info → Run anyway"); the dialog says so. A PowerShell one-liner
     is offered as an alternative.
   - Phones (Android/iOS) get a note that they can't share a model yet (M5). The dropdown still
     lets you prepare a command for a desktop.
3. The runner **detects the local model server by itself**, probing loopback only, in this order:
   Ollama :11434, LM Studio :1234, llama.cpp :8080, vLLM :8000, KoboldCpp :5001, Jan :1337. It
   re-checks every minute. `RAKAZO_RUNNER_MODEL_URL` pins a server.
4. The dialog **polls** every 2 s: *Waiting… (countdown)* → *Paired as "My PC". Connecting…* →
   **"✓ My PC is connected"** plus the models found. Then *Done*. An expired code gets
   **Get a new code**. All models start **off**.
5. The owner switches on the models to offer.

**Re-pairing the same computer** (running the command again, or **New key**) keeps the same
device, models and switches. A **New key** code is bound to that device. Otherwise the runner
proves the old key, which it sends only to the server that issued it.

One-click native install (a signed app with a bundled model) stays **M5**.

### 1.2 Manage computers

Each row in **My hardware**: name, **online / offline** + last seen, runner version, models with
on/off switches, bots using it, groups it may answer in. Actions:
- **Rename**; **Pause sharing** (kill switch: device stays paired, every request fails with the
  offline-style notice); **Resume**.
- **New key** (rotate): issues a new pairing code bound to the *same* device; the old key stops
  working immediately and the running runner is told to stop. Running `pair` again with the new
  code restores it. Bots and grants are kept.
- **Remove** (revoke): confirm dialog listing affected bots. The runner is disconnected and will not
  reconnect; bots on it show *"needs a model"* and their replies fail with a clear notice.

### 1.3 Put a bot on my computer

Bot settings → **Model** → new section **"On my computer"**: pick *device + model* (only enabled
models; offline devices are shown but marked). Saved bot label: **"Runs on My PC · gemma4:26b…"**.
**Stop using my computer** returns the bot to the space default model.
No manual SQL any more.

### 1.4 Use it in a shared group (grant)

- A bot on my computer answers freely in **my private chat** and in **groups I haven't shared**.
- In a **shared group** it does *not* answer until I allow it. In **Share group** the dialog adds
  a section per such bot: toggle **"Let Chief Local answer for people in this group"** with the
  disclosure *"Their messages in this group will be sent to the model on your computer
  (My PC)."*
- Without the grant, a message to that bot in the shared group fails at once with: *"Chief Local
  runs on Carmine's computer and isn't enabled for this shared group."* (No runner call is made.)
- People in the group see a badge next to the bot: **"runs on Carmine's computer"** (+ "offline"
  when it is). They never see device names, hostnames or IPs.
- Turning the grant off takes effect immediately: in-flight answers for that bot in that group are
  cancelled.

## 2. Data model (additive, idempotent)

All in `ensureLocalRunnerTables()` (`CREATE … IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`), same
pattern as M1 and `group_shares`. Nothing is dropped or renamed; `bots` is not altered.

```text
local_runner_devices            (exists; add columns)
  + enabled        BOOLEAN NOT NULL DEFAULT true      -- pause / kill switch
  + platform       TEXT                                -- "linux-x64", from runner
  + revoked_at     TIMESTAMPTZ
  + rotated_at     TIMESTAMPTZ
  status stays 'active' | 'revoked'

local_runner_pairings           (new)
  id TEXT PK, user_id → user ON DELETE CASCADE,
  code_hash TEXT UNIQUE,            -- sha256(normalized code); plaintext never stored
  device_id → local_runner_devices NULL,   -- set for "New key" (rotate); NULL = new device
  name_hint TEXT, attempts INT DEFAULT 0,
  expires_at TIMESTAMPTZ, used_at TIMESTAMPTZ, created_at
  index (user_id, expires_at)

local_runner_models             (new)  -- what each device advertises + owner's on/off
  device_id → local_runner_devices ON DELETE CASCADE, model_id TEXT,
  context_window INT NULL, advertised BOOLEAN, enabled BOOLEAN DEFAULT false,
  last_advertised_at TIMESTAMPTZ, PRIMARY KEY (device_id, model_id)

local_runner_bot_bindings       (new)  -- which device a shared-local bot uses
  bot_id → bots ON DELETE CASCADE PRIMARY KEY, user_id → user ON DELETE CASCADE,
  device_id → local_runner_devices ON DELETE CASCADE, model_id TEXT,
  created_at, updated_at

local_runner_grants             (new)  -- bot may answer in a shared group
  bot_id → bots ON DELETE CASCADE, group_id → chat_groups ON DELETE CASCADE,
  owner_user_id → user ON DELETE CASCADE, created_at,
  PRIMARY KEY (bot_id, group_id)
```

`bots.modelProvider = 'shared-local'`, `bots.modelId = <model id>` stay as in M1, so the existing
executor path and labels keep working; the binding adds the device.

**M1 migration:** on first start, a `shared-local` bot with no binding whose owner has exactly one
active device gets a binding to it, and that device's model row is marked enabled. This covers
Chief Local on Host-001. Anything ambiguous is left alone and shows "needs a model".

## 3. API

Cookie-session routes live under `/api/local-runners/*` (new `local-runner-control.ts`, mounted
next to the gateway in `app.ts`). Every mutation requires `application/json` and the same trusted
origin check as `trustedSocialMutation`, plus a small body limit. Any id the caller does not own
returns **404** (as with the B1 fix), never 403.

| Method & path | Who | Purpose |
|---|---|---|
| `GET  /api/local-runners/devices` | owner | Devices with online state, models, bots, grant count |
| `POST /api/local-runners/pairings` `{os?}` | owner | New code → `{pairingId, code, expiresAt, commands{unix, powershell, windowsCmd, …}}`. A new code cancels the previous unused one; max 10 devices |
| `GET  /api/local-runners/pairings/:id` | owner | `pending / connected / expired` (dialog polling) |
| `POST /api/local-runners/pairings/:id/cancel` | owner | Invalidate a code |
| `POST /api/local-runners/pair` `{code, name, platform, runnerVersion, existing?, adopt?}` | **runner, no cookie** | Redeem code → `{deviceId, token, gatewayWsUrl, reused}`; with `adopt` and a valid key → `{deviceId, name, adopted: true}` (no new key) or `409 {reason}` (code not used). Failed attempts limited per client and globally |
| `GET /api/local-runners/install.sh`, `install.ps1`, `runner/manifest.json`, `runner/files/:name` | public (flagged) | Installers and pinned runner files; no secrets |
| `GET /api/local-runners/config` | anyone | `{enabled, maxDevices}`, so the overlay stays hidden when the flag is off |
| `POST /api/local-runners/devices/:id` `{name?, enabled?}` | owner | Rename / pause / resume |
| `POST /api/local-runners/devices/:id/models` `{modelId, enabled}` | owner | Offer or stop offering a model |
| `POST /api/local-runners/devices/:id/rotate` | owner | New code bound to the device; old token dead now, `bye` sent |
| `POST /api/local-runners/devices/:id/revoke` | owner | `status='revoked'`, `bye`, cancel in-flight |
| `GET  /api/local-runners/offered-models` | owner | Picker data: `[{deviceId, deviceName, online, modelId, contextWindow}]` |
| `GET  /api/local-runners/bots/:botId` | owner | Current binding (for the bot panel label) |
| `POST /api/local-runners/bots/:botId/model` `{deviceId, modelId}` or `{clear:true}` | owner | Writes binding and `bots.modelProvider/modelId` through `commitBotUpdate` so open UIs refresh |
| `GET  /api/local-runners/groups/:groupId/grants` | group owner | Shared-local bots in the group + granted flag |
| `POST /api/local-runners/groups/:groupId/grants` `{botId, allowed}` | group owner | Grant / revoke (revoke cancels in-flight runs of that bot in that group) |

Existing routes touched:
- `GET /api/group-sharing/groups` and `…/:id/messages`: add `runsOn: [{botName, ownerName,
  online}]` for the consumer badge (no device name).
- `router.ts` `bots.update`: accept `shared-local` **only** when it matches the bot's existing
  binding (so the native panel can re-save other fields). New bindings go only through the endpoint
  above. A space default model can't be `shared-local` in M2.
- Gateway `GET /v1/models`, `POST /v1/chat/completions`: accept the new **sl2** run token (§5).

## 4. Runner changes (`runner/`, version `0.2.0-m2`, still no dependencies)

- **`rakazo-runner pair --server URL --code CODE [--name N]`**: calls `/api/local-runners/pair`
  and writes `credentials.json` (dir 0700, file 0600, atomic write). It prints only "Paired as
  <name>"; the token is never printed. A `--code` on an existing device id re-keys it (rotate).
- **`rakazo-runner start|stop|status`** (wraps today's `start.sh` / `stop.sh`); `status` shows
  connected/offline and the offered models.
- **Model discovery**: `GET <loopback base>/models` at start and every 60s; it sends `models`
  frames `{id, contextWindow?}` (Ollama `/api/show` for context, best-effort). `RAKAZO_RUNNER_MODELS`
  becomes an optional local filter instead of the source of truth.
- **Server policy**: on `policy {enabled, allowedModels, maxInFlight}` it refuses `infer.request`
  for anything not allowed, as defence in depth.
- **`bye` handling**: `revoked` / `rotated` stop the reconnect loop and exit with a clear message
  (*"This computer was removed from Rakijazios; pair again"*). A `1008 unauthorized` close stops
  after 3 tries instead of looping forever.
- **Transport**: the default `gatewayWsUrl` is derived from `--server`
  (`https→wss`, path `/api/local-runners/ws`). It **refuses `ws://` to non-loopback hosts** so the
  token never travels in clear. Token stays in the first frame, never the URL.
- **Install**: `install.sh` and a pinned runner tarball are served from the web origin
  (`patches/web/dist/runner/`), with a SHA-256 check. It installs to
  `~/.local/share/rakazo-runner` with a `~/.local/bin/rakazo-runner` shim and checks Node ≥ 22.18.
  No system service in M2.
- Unchanged: loopback-only model URL, `redirect: "error"`, no shell or tools, no listening port.

## 5. Gateway and worker changes

**Gateway (`patches/api/local-runners.ts`)**
- Sessions are keyed **per device** (several per user). M1's "one session per user" goes away; a
  new `hello` only replaces the same device's session.
- `hello` / `models`: upsert `local_runner_models` (advertised flag + context). Bounds: ≤ 200
  models, id ≤ 200 chars, `ws` `maxPayload` ~1 MB, failed-hello limit per IP.
- `policy` is pushed at connect and on every owner change (enable/pause/model toggle).
- `bye{reason}` + close on revoke, rotate and pause; in-flight requests are failed and cancelled.
- Requests are routed by **run** (§5.1), not by "the owner's session".
- In-flight infers are indexed by `runId`, so a grant revoke can cancel them.

**5.1 Run-bound token `sl2` (fixes the 1 h limit)**
`sl2.<ownerUserId>.<runId>.<exp>.<hmac>`, minted in `resolveModelKey`. The HMAC is derived as in
M1 (`ENCRYPTION_KEY` sub-key, new label `…:v2`). The gateway accepts it only if **all** of these
hold:
1. the signature is valid and `exp` (hard ceiling 12 h, env-tunable for tests) has not passed;
2. `runs.id = runId`, `runs.userId = owner`, and status is `leased` or `running`. **The token dies
   when the run ends**, so long runs no longer depend on a 1 h TTL;
3. the run's bot is owned by the owner, is `shared-local`, and has a binding to an **active,
   enabled** device of that owner with the requested model **enabled and advertised**;
4. **the grant rule (§6)** allows this run's thread.

`sl1` is removed; api and worker always deploy together.

**Worker (adapters)**
- `executor.ts`: the preflight mints `sl2` and calls the gateway. Failures map to readable notices:
  offline, paused, model not offered, **not enabled for this shared group**, device removed. None
  of them fall back to another model (D1). `sharedLocalModelIds()` env gating is removed; the model
  list comes from the DB through the gateway.
- `pi-runtime.ts` (**new bind mount**, small patch): in `modelsForRequest`, a `shared-local` branch
  registers the run's model id on the fly (like `registerOpenAiCompatibleRuntime`), passing the
  advertised context window. This lets any offered model work without `RAKAZO_SHARED_LOCAL_MODELS`,
  which becomes optional and unused.
- `model-selection.ts`: unchanged rule (a shared-local override always wins, no fallback).

**WS through the web origin**
New bind mount `patches/web/vite.config.ts`: one proxy entry,
`"/api/local-runners/ws": { target: api, ws: true, changeOrigin: true }`, placed before `/api` in
`preview` (and `server`). The runner then uses `<WEB_ORIGIN>/api/local-runners/ws`, and port 3100
no longer has to be reachable. Feasibility spike first; if vite preview doesn't upgrade, keep
`:3100` and document it. A public deployment behind Caddy/nginx needs `Upgrade`/`Connection`
headers on that path (README note). **Remote PCs need a public HTTPS `WEB_ORIGIN`**; today's
`http://127.0.0.1:5173` only works on Host-001.

## 6. Grant model and enforcement

Grant = row `(bot_id, group_id)` created by the owner of **both** the bot and the group. Default:
none.

Decision function `sharedLocalRunAllowed(run)`, shared by the gateway (authoritative) and the
executor preflight (friendly message). It **fails closed**:

```text
thread = run.thread
if thread.botId == run.botId                → allow   (private 1:1 chat; only the owner can post)
if thread.groupId:
    if no group_shares rows for the group   → allow   (owner-only group)
    elif grant(run.botId, thread.groupId)   → allow
    else                                    → deny "not enabled for this shared group"
if thread.externalConversationId            → deny "not available in external channels" (see decision 2)
otherwise                                   → deny
```

- It covers direct sends, `@mentions` and **handoffs** inside a shared group, because the run's
  thread is the group thread. A handoff to Chief Local in a shared group needs the grant.
- It is checked **on every completion request**, not just at run start. A revoke mid-run blocks
  the next model turn, and the revoke endpoint also cancels in-flight streams.
- Unsharing a group (removing all `group_shares`) makes it owner-only again: allowed, and grants
  are kept for re-sharing.
- UI: the share dialog shows a warning when a shared group has ungranted shared-local bots.
  Removing the M1 rule *"don't add shared-local bots to shared groups"* is part of this PR.

## 8. Security notes

- **Pairing code**: 8 chars, Crockford base32 (~40 bits). Stored only as an **HMAC** (key derived
  from `ENCRYPTION_KEY`), 10 min TTL, single use (atomic claim). Failed redemptions are limited per
  client (10 per 10 min) and globally (60 per 10 min). Behind the web proxy most clients share an
  address, so the global cap is the real guard: guessing 40 bits at 60 tries per 10 minutes is
  hopeless. A new code cancels the previous unused one. The code travels as a CLI argument or env
  variable, **never in a URL**. It does stay in shell history and in the downloaded `.cmd`, which
  is acceptable because it is one-time and short-lived. No long-lived token ever goes into a URL,
  a command or shell history.
- **Installers**: `curl | sh` and the `.cmd` trust the Rakijazios server over TLS, like any
  installer download. Every runner file and the portable Node.js are SHA-256-checked: runner
  hashes come from the server, and Node.js hashes are pinned from nodejs.org's `SHASUMS256.txt`.
  No sudo or admin rights. Removal: `rakazo-runner stop`, then delete the install directory and
  the systemd/launchd/Startup entry.
- **Device token**: 32 random bytes, sha256 at rest. It exists in plaintext only in the `pair`
  response and the runner's 0600 file. It is never shown in the UI or logs. Rotate or revoke takes
  effect at once (DB check plus live `bye`).
- **Run token `sl2`**: bound to owner **and** run, dead when the run ends, redacted like M1.
  Cookie sessions are still refused on `/v1/*`.
- **Every inference is re-authorised** at the gateway: owner, device active/enabled, model
  enabled+advertised, grant. The worker check exists only for nice messages.
- **Runner**: outbound only; `wss` required off-loopback; loopback-only model dial, no redirects,
  no tools or shell; obeys the server allowlist **and** its own local filter.
- **Web**: JSON-only + trusted-origin on all cookie mutations (CSRF). Unknown or foreign ids give
  404. Body limits apply.
- **Privacy**: consumers see "{owner}'s computer", never a device name, hostname or IP. The server
  doesn't store runner IPs. The grant toggle carries the disclosure that group messages go to the
  owner's model.
- **Public repo**: no secrets, codes or tokens in code, tests, fixtures or screenshots. E2E uses a
  temp `RAKAZO_RUNNER_CONFIG_DIR`, so the real `~/.config/rakazo-runner/credentials.json` is never
  touched.
- **No fallback**: every failure path ends in a notice (D1). No operator key is ever used (D2).

## 9. Test plan

**Unit** (`node --test` / vitest)
- Pairing: code format and normalisation, hash, expiry, single use, attempt burn.
- `sl2` mint/verify: tamper, expiry, wrong owner, malformed.
- `sharedLocalRunAllowed`: a table test covering private chat, owner-only group, shared group
  with and without a grant, external conversation, unknown thread, and a revoked or paused device.
- Runner: `pair` writes a 0600 file and prints no token; `ws://` refused to a non-loopback host;
  discovery filtered by `RAKAZO_RUNNER_MODELS`; policy allowlist refuses a model; `bye revoked`
  stops reconnecting.
- Gateway: multi-device sessions, `policy` push, in-flight cancel by runId.

**Postgres integration** (like `group-sharing.postgres.test.ts`)
- User B listing/renaming/revoking A's device, binding A's bot, or granting in A's group → 404.
- A binding needs own bot + own active device + enabled model. A grant needs the group owner and
  the bot to be a member of the group.
- The M1 auto-binding migration is idempotent.

**E2E** (puppeteer in `~/rk-e2e`, temp runner config dir, Mailpit magic links)
1. Owner: My hardware → Add → code → `rakazo-runner pair` → "connected" within 5 s; models listed,
   all off; enable gemma.
2. New test bot → On my computer → 1:1 reply; runner log shows `infer.done 200`.
3. Bot in the shared QA Group, no grant: qa2's message gets the "isn't enabled for this shared
   group" notice, and the runner log shows **no** `infer.request`.
4. Grant on → qa2 gets a reply and sees the "runs on {owner}'s computer" badge.
5. Grant off mid-answer → stream cancelled; the next message gets the notice.
6. Pause → offline-style notice; Resume → replies again.
7. New key → old runner gets `bye` and exits; re-pair → same device, binding and grant intact.
8. Remove mid-session → runner stops for good; bot shows "needs a model"; replies give the notice.
9. Abuse: reuse a code, use an expired code, 6 wrong codes; `/v1/*` with a cookie; an `sl2` for
   a finished run → all rejected.
10. Runner through `:5173` (WS via web origin). `ss -ltnp` before/after shows no new listening
    port. `docker logs` of web/api plus the runner log contain no token or code.
11. Long run: test env with a short token ceiling. An active run past the old 1 h equivalent
    still works; a completed run's token is refused.
12. Regressions: Chief Local (M1) works after auto-binding; 04-e2e; auth/magic-link regression;
    the share/reply/revoke/re-share cycle; the stream-watchdog after an api restart.

**What Rakazo Tester checks per PR**: the E2E items for that PR, the isolation/abuse items (9),
"no token in logs / no new port" (10), and the regressions (12). Report goes to
`~/rakazo-qa/m2-<pr>-report.md` with screenshots.

grant is denied as soon as M2b ships, because the grant check comes with the token. So M2b
includes the deny branch and M2c adds the "allow" UI.

## 11. Decisions (approved 2026-10-08)

1. **Grants are per bot and per group** (toggle in the Share dialog).
2. **External channels** (messaging integrations, team chat) are **blocked** for shared-local bots
   until M3 adds limits; they get a clear notice.
3. **The runner is served by the Rakijazios server itself** as a pinned version with checksums
   (`install.sh` / `install.ps1` / `runner/files/*`).
4. **Up to 10 computers per account**; each bot is bound to one computer (binding arrives in M2b).

Plus: pairing is OS-aware and automatic (§1.1); one-click native install stays M5.

**M1 compatibility.** Devices seeded by the M1 CLI (`paired_via` NULL/`seed`) get the operator's
`RAKAZO_SHARED_LOCAL_MODELS` switched on automatically, so Chief Local keeps answering. The M1
runner and its `ws://127.0.0.1:3100` credentials keep working unchanged. Until M2b binds bots to a
computer, a `shared-local` run goes to the least busy online computer of the owner that offers the
model and has it switched on. The worker is unchanged in M2a.

**Existing installs (after QA of PR #7).** M1 and M2a share `~/.config/rakazo-runner`. The
installer now runs `inspect → pair → stop → swap files → start`:
- `pair` sends the stored key as `adopt: {deviceId, token}` (only to the server that issued it).
  The api keeps the device if it is active, owned by the code's account and the key matches. It
  then uses up the code (the dialog flips to connected) without issuing a new key. Another account,
  an unknown device, or a "New key" code for another device → `409 {reason}`. The code stays unused
  and no failure is counted. A dead key re-pairs normally (backup kept).
- Every ambiguous case is refused with exit 3 before anything is stopped or written. `--replace`
  (`RAKAZO_REPLACE=1` on Windows) pairs as a new device, keeps a backup and revokes nothing.
- One runner per config dir: `run`/`start` refuse while `runner.pid` names a live runner. `stop`
  stops the service and then the pid-file runner (M1 `start.sh`), so the installer never leaves
  two runners on one dir.
Details: [`runner/README.md`](../runner/README.md#existing-installs-upgrade-replace-one-runner-per-folder).

**Feature flag.** `RAKAZO_LOCAL_RUNNERS_UI=1` on the api. When it is off, the overlay stays hidden
and the control/installer routes answer 404. The gateway (`/ws`, `/v1/*`) is unaffected.
